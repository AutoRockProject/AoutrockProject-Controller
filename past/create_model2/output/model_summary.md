# 決定木モデル v2 - モデルサマリー

## 改善内容

**v1 との差分:** ノイズデータ（ID値）を完全除外し、メインユーザー7名のみで訓練・評価

---

## 1. モデル概要

**モデル名:** Decision Tree Classifier v2 (決定木分類器 - メインユーザー版)  
**目的:** 格闘ゲームのコントローラー入力パターンからプレイヤー（ユーザー）を判定する  
**対象:** 7名のメインユーザーのみ

---

## 2. 目的変数（従属変数）

| 変数名 | 説明 | 値 |
|--------|------|-----|
| **user** | プレイヤー名（メインユーザーのみ） | 7クラス：jin, keita, kotaro, akira, ryo, nakamura, yamaguti |
| 分類対象 | - | **ノイズデータID値は完全除外** |

---

## 3. 説明変数（独立変数）

合計28個の特徴量を使用（v1と同一）

### 3.1 ボタン入力
- **A** - パンチボタン
- **B** - キックボタン
- **RB** - 右ショルダーボタン
- **LB** - 左ショルダーボタン
- **RT** - 右トリガー
- **LT** - 左トリガー
- **SELECT** - セレクトボタン
- **START** - スタートボタン

### 3.2 方向入力
- **Up, Down, Left, Right** - 方向キー
- **UpLeft, UpRight, DownLeft, DownRight** - 斜め方向

### 3.3 コマンド検出
- **Shoryuken** - 昇竜拳コマンド検出（→↓↘ + パンチ）
- **Hadoken** - 波動拳コマンド検出（↓↘→ + パンチ）

### 3.4 ボタン組み合わせダミー
- **Right_Jump** - 右 + ジャンプ
- **Left_Jump** - 左 + ジャンプ
- **Right_Kick** - 右 + キック
- **Left_Kick** - 左 + キック
- **Punch_Kick** - パンチ + キック
- **Jump_Punch** - ジャンプ + パンチ

### 3.5 動画処理特徴量
- **standing_right** - プレイヤーが画面右側に位置（StateXの正負から推定）
- **standing_left** - プレイヤーが画面左側に位置
- **body_right** - キャラクターが右向き
- **body_left** - キャラクターが左向き

## 9. 精度向上に向けた分析と提案

### 9.1 なぜ精度が低いのか？

**原因1: 複数ユーザーの類似プレイスタイル**
- akira と kotaro、jin などは似たボタンパターンを使用
- ボタン入力のみでは区別困難

**原因2: 特殊コマンドが検出されない**
- Shoryuken, Hadoken が0%の重要度
- コマンド検出ロジックの改善が必要

**原因3: 動画特徴量の不十分性**
- standing_right, body_right は StateX の符号から推定
- より詳細な骨格検出が必要

### 9.2 精度向上の提案

#### 短期的な改善（データレベル）
1. **コマンド検出ロジックの修正**
   - 現在: 昇竜拳を→↓↘で検出
   - 改善: より多くのフレーム履歴を確認、タイムスタンプ差を活用

2. **時間軸特徴量の追加**
   - 連続フレーム間のボタン変化率
   - ボタン押下時間の長さ
   - コンボパターン

3. **キャラクター情報の活用**
   - 選択キャラクターの情報を特徴量に追加
   - 各プレイヤーが好む使用キャラを学習

#### 中期的な改善（モデルレベル）
1. **アンサンブル学習**
   - Random Forest, Gradient Boosting の試行
   - クラスの不均衡（akira vs kotaro）への対応

2. **階層的分類**
   - 最初に「識別困難なユーザーグループ」を判定
   - その後、グループ内で細分化

#### 長期的な改善（特徴量レベル）
1. **動画処理の実装**
   - 骨格検出（OpenPose等）
   - 手足の動き解析
   - キャラの向き判定

2. **音声特徴量の追加**
   - ボタン音のパターン
   - ゲーム音声の特徴

3. **ユーザー別訓練モデル**
   - 二値分類器を複数構築（1対1）
   - より高い精度の可能性

## 10. 結論

### v2 の評価
- ✅ **ノイズデータ完全除外:** メインユーザー7名のクリーンなデータセット
- ✅ **識別性の高いユーザー発見:** kotaro, jin で約53%の精度を実現
- ⚠️ **精度の限界:** ボタン入力のみでは全ユーザー識別は困難
- ⚠️ **コマンド検出失敗:** 特殊コマンド検出ロジックの改善が必須

### 推奨される次のステップ
1. コマンド検出ロジックのデバッグ
2. 時系列特徴量の追加
3. より複雑なアルゴリズムの検討（Random Forest等）
4. 動画処理特徴量の実装
