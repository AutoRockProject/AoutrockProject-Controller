## 3. 用語解説

### RF重要度とは

RF（Random Forest = ランダムフォレスト）は「決定木」を500本生成して多数決で予測するモデルである。
各決定木は「この特徴量でデータを分割すると、プレイヤーの分類がどれだけ純粋になるか」を基準に学習する。

**RF重要度** は、各特徴量が500本の木全体を通じて「分類に貢献した度合い」を0〜1の範囲でスコア化したものであり、全特徴量の合計が1.0になるよう正規化されている。

| 値の目安 | 意味 |
|---|---|
| 0.08 前後 (上位) | その特徴量がないと予測が大きく狂う — 最重要 |
| 0.03〜0.05 (中位) | 他の特徴量と組み合わせて貢献している |
| 0.00 (下位) | 全プレイヤーで値がほぼ同じ → 識別に貢献しない |

例: `jump_rate = 0.0838` は全28特徴量中で最高スコアであり、ジャンプ頻度がプレイヤー識別において最も信頼できる手がかりであることを示す。
逆に `A_used = 0.0000` は、Aボタン使用有無がどのプレイヤーでも同様であるためモデルに無視されていることを意味する。

### 特徴量カテゴリの定義

28列の特徴量は「どこから取得した情報か」によって5カテゴリに分類している。

| カテゴリ | 取得元 | 内容 |
|---|---|---|
| **行動** | `output/train.csv` / `test.csv` (フレーム単位集計) | プレイ中の動き方の集計値。ジャンプ・しゃがみ・コンボ頻度など、1試合分のフレームログを集約して算出 |
| **コマンド** | `data/command_events.csv` (ルールベース検出) | 波動拳（↓↘→ + 攻撃）・昇竜拳（→↓↘ + 攻撃）の入力シーケンスをルールで検出した回数・頻度 |
| **フェーズ** | `output/train.csv` / `test.csv` (時系列分割) | 試合を時系列で4等分し、各区間（phase1=序盤〜phase4=終盤）ごとの入力密度を算出。序盤・終盤どちらで活発かという「試合の流れの個人パターン」を捉える |
| **特殊技・距離** | `Scripts/video_cache/` (動画解析) | MP4動画をフレーム単位で解析して取得した視覚情報。波動拳モーション検知フラグと、画面上のキャラクター間距離（ピクセル） |
| **ボタンダミー** | `output/train.csv` / `test.csv` (ボタン列) | 試合中に特定のボタンを1回でも押したかどうかを 0/1 で表したもの。押下率（何回押したか）ではなく「使ったか使わなかったか」の2値 |

### 誤分類パターンの考察

3件の誤分類はすべて jin / keita / ryo の三つ巴:

- `jin → kotaro` @ keita_jin_2: keita戦でjinがkotaro風の動きをした
- `keita → jin` @ keita_ryo_2: ryo戦でkeitaがjin風の動きをした
- `ryo → keita` @ kotaro_ryo_2: kotaro戦でryoがkeita風の動きをした

**仮説**: 対戦相手のスタイルに引っ張られて本来のプレイスタイルが変化する。  
→ 改善策: 対戦相手のプロファイル情報を特徴量に追加する。

### v4 モデル候補特徴量

jin/keita/ryo 混同への直接的な対策として、以下の特徴量追加を検討する:

| 特徴量 | 説明 | 期待効果 |
|---|---|---|
| `opponent_jump_rate` | 対戦相手の `jump_rate` | 相手スタイルによる自分の行動変化を吸収 |
| `opponent_combo_rate` | 対戦相手の `combo_rate` | 同上 |
| `relative_input_density` | 自分の `input_density` ÷ 対戦相手の `input_density` | 試合の攻守バランスを相対値で捉える |
| `win_loss_flag` | 試合の勝敗 (取得可能な場合) | 勝ち試合・負け試合でプレイスタイルが変わる効果を制御 |
